# MethodDka 開発憲章 (Constitution)

本憲章は、高精度多項式数値解法システム「MethodDka」における設計、実装、テスト、およびドキュメント運用の根本原則を定める。本リポジトリにおけるすべてのコード変更および機能拡張は本憲章に準拠しなければならない。

---

## 1. コア原則 (Core Principles)

### 原則 I: ライブラリ・ファースト (Library-First & UI-Decoupled)
すべての数理アルゴリズム（複素数演算、ユンの平方無因子分解、Fujiwaraオートスケーリング、Aberth初期値、DKA同時反復ループ、ホーナー法残差検算）は、DOM、Window、ブラウザ固有APIに一切依存しない独立した Node.js / ESM ライブラリとして実装する。
UI（Web / Electron）は数理コアのコンシューマー（利用者）に過ぎず、計算コア単体で CLI、CI、バッチ処理から実行可能でなければならない。

### 原則 II: 精度解釈とドキュメント完全性 (Precision Integrity & Honest Metrics)
- **出力形式と精度の厳密な区別**: 「実部有効数字200桁・虚部 $10^{-200}$ 単位丸め」は出力形式の仕様であり、数学的な正解有効桁数を保証するものではない。
- **後退誤差指標の明示**: ホーナー法による正規化残差 $\eta(z) = |P(z)| / \sum |a_i||z|^{n-i}$ や係数再構成残差は後退誤差および根集合の数値的整合性の指標であり、真の前進誤差や有効桁数の証明ではない。残差が $10^{-307}$ であっても「307桁正しい」等の誤解を招く表現をコードコメントやドキュメントに含めてはならない。
- **ガード桁の確保**: DKA本体は 260 桁内部精度（60ガード桁）、前処理は 320 桁固定精度（または BigInt 厳密演算）を厳格に保持する。

### 原則 III: テスト駆動 ＆ ゴールデンベンチマーク (Test-First & Benchmark-Driven)
機能追加やリファクタリングは常にテスト駆動（TDD）で行う。以下のベンチマークスイートをCIで常に実行し、リグレッションを防止する：
1. **整数係数重根テスト**: $(x^2+1)^2 = x^4 + 2x^2 + 1 = 0$（BigInt による厳密 GCD 判定）
2. **20次ウィルキンソン多項式 ($W_{20}$)**: 既知根 $1 \dots 20$ との照合、正規化残差 $\le 10^{-180}$（20/20合格）
3. **50次ウィルキンソン多項式 ($W_{50}$)**: 50根の反復収束および残差適合
4. **100次ウィルキンソン多項式 ($W_{100}$)**: 反復上限到達時の安全停止と残差適合（100/100合格）

### 原則 IV: セーフティガードと安全なフォールバック (Safety Guards & Deterministic Fallback)
ユンの平方無因子分解前処理において、以下の3条件を必ず検証する：
1. 多項式除算の余りノルムが許容値 $\epsilon$（$10^{-220}$ または整数厳密割り切れ）以下であること。
2. 抽出された各因子 $Q_k(x)$ が平方無因子（$\gcd(Q_k, Q_k') = \text{const}$）であること。
3. 重複度を重み付けした次数再構成 $\sum k \cdot \deg(Q_k) = \deg(P)$ が元の次数と厳密に一致すること。
いずれかの検証に失敗した場合は、詳細な診断ログを出力した上で、例外終了させず元多項式 $P(x)$ をそのまま DKA ソルバーへ渡すフォールバックを実行する。

### 原則 V: クライアント完結 ＆ プライバシー・バイ・デザイン (Zero-Leakage Privacy)
多項式計算、前処理、残差検算はすべてユーザーの手元（ローカルマシン / ブラウザ環境）で完結する。
Google Gemini API を用いた解説機能は、ユーザーが明示的に API キーを入力して実行ボタンを押下した瞬間に限り呼び出し、送信直後に入力欄をクリアし、キーおよび結果を永続ストレージ（LocalStorage等）に保存してはならない。

## 2. 開発ワークフローと品質ゲート (Governance & Quality Gates)

1. **仕様定義 (Spec) 必須**: すべての機能改修は、事前に `.specify/` または要求仕様書に受け入れ条件と入出力インターフェースを明文化してから実装を開始する。
2. **静的検査と型安全性**: TypeScript または JSDoc による型チェック、ESLint による構文・スタイル規約を徹底する。
3. **リポジトリ同期規約**: メインリポジトリ `MethodDka` で検証完了したコードは、ネイティブ版 `MethodDkaWindows11` に正確に反映・同期する。
